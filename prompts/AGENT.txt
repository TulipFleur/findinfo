findinfo · Agent workflow prompt (copy and use)

How to use: copy "Task" through "One-liner version" into a fresh agent session and replace the placeholders.

| Placeholder | Meaning | Required |
|---|---|---|
| `{{TARGET}}` | Verified root domain used by the CLI examples; for several roots repeat `--domain` / `--match` (do not pass a bare space-separated list) | required before collection |
| `{{NAME}}` | Company name; may contain spaces and non-ASCII, **quote it**; leave empty if unsure | optional |
| `{{TASK}}` | Task name isolating the asset graph; recommend the main domain like `example-com`; non-ASCII allowed | required |
| `{{RUN_ID}}` | run id returned by `run --background`; **only known at runtime**, do not pre-replace | runtime |

Goal: carry one full collection job through its actual result — never stop at a passive first pass or at “started”. This file is a **workflow template**; capabilities and parameters are defined by `SKILL.md` (the machine entry) and `--help` — on conflict, tell the user. Rules in [SKILL.md](SKILL.md) §5, failures and progression in [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).

## Task

Collect the assets of **{{TARGET}}** (company name: {{NAME}}), producing an asset graph with provenance/confidence, an endpoint table and a real HTML report.
“Collect XX assets” defaults to passive discovery, DNS, probe, IP aggregation, ports, vhost, crawl and extract. Only an explicit passive-only or single-stage request narrows the plan. Active stages send traffic to the supplied target. Dictionary brute force is optional, outside this default.

## 0. Locate the skill (30 seconds, mandatory)

Use Python (runs on any host):

```bash
python -c "import os,pathlib;c=[os.path.expanduser(p) for p in ('~/.agents/skills/findinfo','~/.claude/skills/findinfo','~/.codex/skills/findinfo')]+[os.getcwd()];print(next((d for d in c if pathlib.Path(d,'findinfo.py').is_file()),'NOT_FOUND'))"
```

`cd` into the printed directory, then:

```bash
python findinfo.py --task {{TASK}} doctor
```

Three mandatory doctor checks: `tools_summary.all_in_bin == true` (count = `tools_summary.total`), `environment.python_ok == true`, `environment.net_egress.any_reachable == true`. If any fails: stop, report the blocks verbatim, install nothing, force no run. Missing mapping keys/Cookie are source gaps, not reasons to abandon the available keyless chain.

## 1. Target and scope

Use the target supplied by the user. Do not routinely ask for authorisation or whether subsidiaries should be included before starting. Add related companies only when the user explicitly names them; related assets found during collection are candidates, not an automatic scope expansion.

- If a trusted domain is supplied, use it directly. For multiple roots, repeat `--domain` (and `--match` for delivery).
- If only a company name is supplied, use available entity anchoring. If Cookie/mapping keys are absent or cannot establish an anchor, use available search to verify the official root domain from reliable company evidence, then use that verified domain as `{{TARGET}}`. Never guess a domain or select an ambiguous company. Only when no trustworthy seed can be verified, explain the blocker and request a root domain.
- Keep the same explicit task/home and run_id in every follow-up command. Missing credentials alone do not shrink the requested stages.

## 2. Rules

The rules this loop relies on are stated once, in [SKILL.md](SKILL.md): one JSON line on stdout (§0), scope every store read (§1), and the hard rules (§5). Read them there before step 3; they are not paraphrased here, so the two cannot drift apart.

## 3. Default full job (one background run)

Start the full job once. Do not run a separate foreground passive checklist first:

```bash
python findinfo.py --task {{TASK}} run --domain {{TARGET}} --active --ports --vhost --crawl --background --rounds 3
```

Save the returned run_id and follow section 6 until the job finishes. Use progress from this same job for brief updates; a passive summary is not the final delivery. The underlying CLI still defaults to passive when active flags are omitted, for compatibility: never mistake that low-level default for this Agent workflow.

## 4. What the full job must cover

### 4.1 Discovery and credential gaps

The job collects `onepass -> certs -> subs`, then available domain/ICP mapping. Mapping is the quota-spending source; its task ledger reuses answers unless `--remap` explicitly asks again. Entity anchoring needs its Cookie. A domain seed does not need that Cookie.

When a mapping key/Cookie is missing, skip only its dependent source and record the coverage gap. Continue every available keyless stage. Do not switch to passive-only, deliver early, request credentials as a prerequisite, or resume solely because a key is missing. Do not automatically persist `--no-mapping` merely because keys are currently absent; an explicit opt-out is a different source policy.

### 4.2 Verification and expansion

The full job continues in this order:

```text
dns -> probe -> ipagg -> ports -> vhost -> crawl -> extract
```

DNS filters wildcard noise; probe records liveness/fingerprints/IPs; ipagg removes CDN collision candidates; ports/vhost find services; crawl/extract expand in-scope Web/JS clues. A stage with no valid input may return `no_input`; report that reason rather than claiming it sent traffic. Missing tools, time/round limits and unavailable sources must remain visible in coverage.

### 4.3 Optional dictionary brute force (active)

Only add dictionary brute force when it is requested or needed as a stated extension. ksubdomain sends raw DNS packets and needs Npcap. The standalone command is a reference for an explicitly requested single stage, not part of the default foreground flow:

```bash
python findinfo.py --task {{TASK}} brute --domain {{TARGET}} --wordlist sub --tool-timeout 900   # add --bandwidth 5m to go bigger
```

Keep the user's target scope and the tool's traffic/budget limits.

## 5. Reflow loop (the heart of "full", do not skip)

`extract` surfaces new domains/IPs. **Reflow every round** until convergence:

```text
new domains from extract
  -> dns --from-store --scope {{TARGET}} (resolve + wildcard filter)
  -> probe --from-store --scope {{TARGET}} (new live hosts)
  -> ipagg -> ports -> vhost (new shared IPs)
  -> crawl -> extract (next round)
```

Read the actual result and coverage for convergence. A stable domain count alone is insufficient: `coverage.work_queue.outstanding > 0` means `partial`/`work_pending`; `coverage.js_queue` mirrors the run-scoped queue. The Agent command explicitly uses 3 rounds; the low-level CLI defaults to 1. If a budget ends with pending work, state the partial result and reason; continue only when recovery or an appropriate budget extension can advance it. A wait timeout is not a failure: call wait again on the SAME run id, never start a second run.

## 6. Long jobs: background + bounded wait (no nohup)

```bash
# 1) start: returns the run_id and result paths immediately
python findinfo.py --task {{TASK}} run --domain {{TARGET}} --active --ports --vhost --crawl --background --rounds 3

# 2) bounded wait: 30 seconds max per call, returns early on progress/completion/failure
python findinfo.py --task {{TASK}} wait --run {{RUN_ID}} --timeout 30
```

Reading and progression (full table in [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md) §2, §3):

| Return | What you do |
|---|---|
| `running` (`timed_out` or `changed`) | Wait window ended / progress happened: keep calling `wait` on the same run_id, **do not restart**; on `changed:true` give the user a one-line stage summary |
| `completed` | Read `result`/`coverage`, go to section 7 delivery |
| `failed` | Read `coverage.failed_stages` + `last_error`; resume the same run only when the failure is recoverable |
| `cancelled` | Report what was collected; do not restart |
| `interrupted: true` | `reaped_by_host: true` → switch to foreground; `false` → `run --resume` |

- `percent` in compact `wait` (or `progress.percent` in `status`) being **null** means the total is unknown: say "N rows processed", never invent a percentage.
- `reused: true` = an identical run already exists: use its run_id, do not start another. Address jobs **by run_id only**.

## 7. Delivery: generate and link the HTML

After the job reaches a terminal state, inspect its verdict and coverage. **Delivery is two steps** — read `brief`, then actually run `report`; do not assemble Markdown tables as a substitute:

```bash
# your read API: include --run so coverage gaps reflect THIS run
python findinfo.py --task {{TASK}} brief --run {{RUN_ID}}
# human deliverable: HTML only by default, tied to the same run
python findinfo.py --task {{TASK}} report --run {{RUN_ID}} --match {{TARGET}} --slug "{{TASK}}"
```

Deliver the actual returned `paths.html` as a clickable file path, with a short statement of the end reason, executed/failed/not-run stages and material gaps. Never invent an artifact path or replace the report with a hand-written `.md` file. Add `--with-md` only when Markdown is explicitly requested; `--with-json` / `--with-brief` remain opt-in. `brief` writes no files.

`coverage.source` is the run id read; `known=false` means no run was read (**not** "no gaps"). Truncated arrays report kept/total in `truncated`. Never read a large `report.json` into context.

## 8. One-liner version (when only a minimal prompt is wanted)

```text
Use the findinfo skill to fully collect the assets of {{TARGET}}.
0) Locate the skill directory (python -c over candidate paths) -> doctor (require tools_summary.all_in_bin=true)
1) Use the supplied target without a routine confirmation gate; related companies need explicit user inclusion.
   Company-only input without usable anchoring -> search to verify its official root domain; never guess; request a seed only if verification fails.
2) Default means full collection, not a passive first pass; missing mapping keys/Cookie skip only dependent sources.
3) Start one job: python findinfo.py --task {{TASK}} run --domain {{TARGET}} --active --ports --vhost --crawl --background --rounds 3
   and take the run_id (reused=true means one is already running — use its run_id)
4) Wait: wait --run <run_id> --timeout 30; a timeout returning running only ends that wait window —
   keep waiting on the same run_id, never restart, never declare completion early
5) Results: completed -> status --run <run_id> for result/coverage; failed/interrupted -> inspect before recovery;
   budget exhausted -> state the shortfall; missing key alone never ends the available keyless chain or justifies a retry.
6) Deliver: python findinfo.py --task {{TASK}} brief --run <run_id> (you read this), then python findinfo.py --task {{TASK}} report --run <run_id> --match {{TARGET}};
   return the actual HTML path and the end reason/stage gaps. HTML is the only default report file; Markdown/machine files need explicit opt-in.
Only an explicit passive-only/single-stage request narrows the workflow. A justified no_input is not executed traffic. Never install tools yourself. Parse the single JSON line on stdout; do not cat large files or hand-write a Markdown report.
```
