### P0-1：`--task` 位置陷阱

**原症状**：`run --task X`（文档全部示例的写法）rc=2，报
`argument --task-timeout: invalid float value: 'X'` —— argparse 前缀匹配把它当成了 `--task-timeout` 的缩写，错误信息指向错误的参数。

**修法**：
1. `_prescan_task(argv)` 在 `lib.core` 导入**前**扫描整个 argv，两种位置都识别。这一步是必须的：`core` 在 import 时就解析 `HOME/DATA/RUNS_DIR`。
2. 给所有子解析器注册 `--task`，`default=argparse.SUPPRESS` —— **这是关键**。若用真实默认值，正确写法 `--task X run` 会被子解析器的默认值覆盖成 `None`（已实测验证过这个陷阱）。
3. `_prescan_task` 拒绝把子命令名当作 task 值：`--task run doctor` 中 `run` 是子命令不是任务名。
4. 新增 `test_subcommand_guard_matches_the_real_parser` 守护 `_SUBCOMMANDS` 与真实解析器一致。

### P0-2：`clean --all` 无确认清库

**原症状**：`clean --all` 直接 `DELETE FROM assets/endpoints`，rc=0，无确认、无预览。资产图是各任务共享的，误调一次即全清。

**修法**：
- 无 `--yes` 时只返回 `{"error": ..., "would_delete": {...}}`，`assets: 0`、`deleted: false`，**不碰库**
- `--dry-run` 优先级高于 `--yes` 检查（预览本就不删，不该被确认门挡住）
- `--dry-run` 对 `--keep` / `--match` 也生效，且与真实运行走**同一个 SELECT**，保证预览数与实际删除数一致

## 行为变化（对调用方 / 下游 agent 的影响）

1. `--task` 现在**两种位置都合法**：`--task X run ...` 与 `run ... --task X`。文档统一示范前置写法。
2. `clean --all` **不再是即删操作**，必须 `--all --yes`；裸调 `--all` 返回 `deleted: false` 并给出预览。
3. 新增 `clean --all --dry-run` / `clean --keep <x> --dry-run` / `clean --match <x> --dry-run`。
4. `Store.purge()` 新增可选参数 `dry_run`，返回 dict 多一个 `"dry_run": true` 键。**旧调用不受影响**（默认 False）。
5. 成功删除时，`clean` 的输出新增 `"deleted": true`。
