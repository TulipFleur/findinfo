### 一、作业执行与恢复（P1）

1. **作业定位不再依赖会话上下文**
   `_ctx_prefix()` / `_followup()`：`next`、`status.next_steps`、resume 返回的每条后续命令
   都带全 `--task` 与 `--home`。新增顶层 `--home`（在 import core 前预扫描，因为 core
   在 import 时解析 HOME/DB）。验收：新进程清空环境后照抄 `next`，能定位同一 run_id。

2. **spawn 失败不再永久 queued**
   - `jobs.spawn()` 捕获 Popen 异常 → 写 `state=failed` + `last_error.type=spawn_failed` + hint，再抛错
   - `derive()`：`queued` 且无 pid 超过 `QUEUE_GRACE=20s` → `alive=False, interrupted=True`
   - `find_inflight` 跳过 terminal 行 → 重试能真正启动
   - `_start_background`/`_resume_run` 捕获 spawn 失败并输出 run_id（不吞成"已启动"）

3. **attempt 结果隔离**
   - `summary.jsonl` 每条带 `attempt`
   - `_last_summary(rd, attempt)` 逐行反查本 attempt；拿不到就返回 None
   - 拿不到时 `worker_main` 显式写 `result.status=failed / reason=no_summary_for_attempt`，
     绝不沿用上一 attempt 的 `complete`。历史仍留在 summary.jsonl 供追溯。

4. **超时与 resume 参数**
   - 修 `task_timeout` 键名断裂：spec 现在写**顶层** `task_timeout`（worker 读的就是它），
     `budget.task_timeout_sec` 保留给 status
   - `_foreground_argv` 回放 `--task-timeout`
   - `_merge_resume_argv()` + `_mark_explicit()`：只有命令行**显式键入**的
     rounds/time-budget/tool-timeout/task-timeout/force-stage 会覆盖 spec，其余继承；
     目标与范围不可变（不在可覆盖列表里）

### 二、结果与覆盖度真实性（P2）

5. **统一 outcome 词汇**（lib/core.py）：`ok/empty/partial/failed/timeout/unavailable/budget`
   + `combine_outcome()`（最差获胜）+ `outcome_from_rc()` + `outcome_hint()`。
   `t_subs` 逐源记录 outcome 并全失败返回 `ok=False`；`t_onepass` 不再硬编码 `ok:True`；
   run 的 subs/onepass 阶段在**全失败时抛 StageError**（不写成功断点）。

6. **显式种子必进验证集**：`--domain` 的域名以 `source="seed:user", confidence=0.5` 入库，
   dns 输入显式并上 `named`。验收：被动全空时种子仍被 dnsx 解析（0.5→0.8）。

7. **JS 工作队列**（`js_queue` 表）：`js_enqueue/js_claim/js_finish/js_stats`。
   `t_extract` 先入队再按预算认领，失败项可重试，done 不再认领；
   返回 discovered/attempted/succeeded/failed/pending/budget_hit；
   `coverage.js_queue` 暴露待处理量；密钥**脱敏**（前 4 位+长度）。

8. **阶段状态与 coverage**：`_not_run_stages` 重写——checkpoint 命中（无论有无 resume 回调）
   一律算已覆盖；`no_input/no_hosts` 单列不算缺口；failed 优先于 succeeded 判定。
   `_plan_stages` 不再计划被 `--no-icp/--no-onepass` 关闭的阶段。
   coverage 新增 `stage_states`（逐阶段状态）与 `disabled_stages`。

### 三、证据与关系（P3）
